# x1080x-ex

面向 `1080xin.com`（兼容原 `agaghhh.cc`）/ `hdblog.me` / `sehuatang.org` 等站点的 Tampermonkey 增强脚本。

## 主要功能

- **一键下载**：旧版 Discuz 下载主楼附件、图片、Preview 大图，并将磁力链转换为 `.torrent`；新版 `/resources/` 详情页支持正文图片和 Preview 下载。新版附件由网站自身的授权/计次按钮下载，脚本不绕过权限或代替原生按钮。
- **下载保护**：下载进行中在浏览器标签标题显示“⬇ 下载中”，关闭标签页时弹出浏览器确认提示，完成后自动恢复。
- **自动命名**：自动识别番号、清理标题并处理 Windows 非法字符，支持 FC2、1PON、CARIB 等规则。
- **Preview 大图**：agaghhh 按番号优先从 hdblog 获取 Preview；FC2 会自动只用纯数字部分联动（如 `FC2-4906444` → `4906444`）；hdblog 无结果或 Preview 失效时可回退到 JavFree，再回退 FANZA / MGStage 官方源。HDblog 文章页自身无可用 Preview 时也可从 JavFree 补图。
- **Pixhost 解析**：自动解析 Preview 原图，并对 `pixhost.to` / `pixhost.cc` 等同一资源进行去重；同一文章同时有普通版和 4K Preview 时优先普通版，仅在普通版不可用时回退 4K。
- **跨站搜索**：agaghhh 与 hdblog 标题旁提供 `🔍`，可按番号直接搜索另一站；FC2 标题会去掉 `FC2 / PPV` 前缀，仅搜索数字番号。
- **复制番号**：agaghhh 与 hdblog 标题旁提供 `📋`，一键把当前番号复制到剪切板。
- **FC2CMADB 搜索 HDBLOG**：在 FC2CMADB 作品列表（例如演员页面）点击封面左上角纯数字番号，直接以该号码在 HDBLOG 搜索并在新标签页打开；封面原链接保留不变，兼容动态分页。
- **真实演员查询**：主楼演员信息为空时，可通过 av-wiki 查询并补充到下载文件名。
- **批量打开**：列表和搜索页支持顺序后台打开主题；执行期间标签标题显示“↗ 批量打开中”，关闭或刷新页面会由浏览器确认，完成/停止后自动解除。
- **搜索增强**：支持关键词过滤、搜索结果仅 1 个主题时自动跳转。
- **qBittorrent 回退**：公共 torrent 缓存失败时，可通过 qBittorrent 5.2+ 获取 metadata 并导出 `.torrent`。
- **98堂浮动助手**：右侧可拖动并记住位置的楼主附件列表，每个文件旁提供定位、下载图标，下方提供快捷回复，滚动长帖时保持可见。

## 设置

设置窗口已统一为分类导航布局：桌面端左侧分类、右侧配置，窄屏自动调整为顶部横向分类。仅显示当前类别，底部始终保留 **取消 / 保存**；切换类别不会丢失尚未保存的修改。

- **x1080x**：批量打开、浏览记录、搜索与过滤、下载与按钮、预览与演员；qBittorrent 回退设置独立成类。
- **HDBLOG**：文章布局、下载与按钮、预览与修复、批量打开、浏览记录、关键词过滤；额外图床域名独立成类。
- **JavFree**：搜索功能、文章操作。
- **FC2CMADB**：只有一项开关，仍保留简洁的 Tampermonkey 菜单设置。
- **98堂**：独立的附件定位、附件下载、快捷回复、回复后可见提示开关，回复短语和按钮位置设置。

原有配置键、保存行为、默认值及开关依赖均保持不变；例如关闭批量打开后，其间隔和历史相关选项仍按原有规则禁用。


### x1080x（1080xin.com / agaghhh.cc）

已适配改版后的 `/boards/<ID>` 列表和 `/resources/<ID>` 详情页面：列表的「批量打开未浏览（数量）」按脚本记录跳过已浏览主题；未开启跳过功能时显示「批量打开本页（数量）」。悬浮提示说明后台顺序打开、随机间隔和再次点击停止的行为。

详情页的下载、搜索和复制按钮统一放在「收藏」左侧，页面重绘后维持顺序。下载按钮采用紧凑的 44×36 图标样式，下载时在图标下显示 `1/3` 等数量，结束后显示绿色勾选或失败图标，2.5 秒后恢复。详细统计仍在操作区左侧空白处，超长省略并可悬浮查看，状态变化不会挤动右侧按钮。

React 重绘下载按钮时会恢复正在进行的进度和禁用状态，避免重复触发同一批任务；关闭下载增强后也不会插入空状态区域。

总数按实际计划的图片、Preview、种子和原生附件任务计算。图片等文件支持 `GM_download` 时等待保存成功回调后计入「已保存」，保存失败显示具体原因；无此接口时使用临时链接发起下载。已校验的 `.torrent` 沿用浏览器原生 Blob 下载，避免新增的 `GM_download` 扩展名白名单限制阻断原有种子保存。浏览器下载保留 Blob 地址 10 秒，统计为「已发起」，需在浏览器下载列表确认。

跨站图片请求遵循图片元素的 `referrerpolicy`（HXMMDD 使用来源站点 origin，`no-referrer` 显式清空 Referer），备用路径也沿用原图片策略。HXMMDD 会在 `/images/` 与 `/images-v2/` 间尝试备用地址，单个文件失败不会阻止其他文件保存。

ZIP/RAR 等新版站内附件沿用网站的报价、CSRF、额度申请和下载凭证流程。免费/额度下载取得服务器授权后，由脚本按原有「番号＋清理后的帖子标题」命名保存，并保留原扩展名；ZIP 会检查文件头，避免把错误页保存为附件。申请失败不会再点击网站按钮重复消耗额度，重试沿用同一幂等键；涉及点数购买时仍交给网站原生按钮确认，暂不由脚本更名。所有请求仍受网站登录、权限、额度和安全验证限制。

**跨站搜索**：HDBLOG / JavFree → x1080x 现使用新版 `https://1080xin.com/search?q=番号`，例如 `FC2-PPV-4994798` 会搜索 `4994798`。新版 `/boards/` 的批量工具栏放在分页控件上方；保留原有访问标记、只打开未访问主题、跨页定位按钮和设置键，并在客户端切换分页后重新同步。

**备注**：改版后的 `/search` 结果结构未提供样本，旧 Discuz 搜索页的关键词屏蔽/单结果自动跳转逻辑暂未覆盖新版搜索页。

### sehuatang.org（98堂）

通过 Tampermonkey 菜单 **⚙️ 98堂设置**，或双击浮动栏顶部「98堂助手」打开设置：

- **回复短语**：开启快捷回复时不能为空。保存后立即生效，定位、下载、快捷回复和隐藏内容提示互相独立；两个图标都关闭时不列出可下载文件，隐藏提示仍由自己的开关控制，全部关闭后移除浮动栏及其监听和计时任务。
- **按钮位置**：拖动浮动栏顶部可移动，松开后记住位置；窗口缩小时自动限制到可见区域。在设置中点击「重置按钮位置」后保存，即可恢复右侧默认位置。

98堂设置独立存储，不与 x1080x / HDBLOG 设置混用；旧版本没有这些设置键时，定位图标、下载图标、快捷回复和隐藏内容提示均默认开启，旧版开关值继续沿用。仅在 `sehuatang.org` / `www.sehuatang.org` 的帖子详情页显示浮动栏。

## 域名

默认支持：

- `1080xin.com`（x1080x 当前默认域名）
- `agaghhh.cc`（原域名，保留兼容）
- `hdblog.me`
- `javfree.me`

Tampermonkey 菜单中的 **🌐 设置 x1080x 站点域名** 用于修改当前站点地址，默认 `1080xin.com`。保存后，跨站搜索及浏览进度会使用该地址；旧域名仍可识别，原有历史记录不受影响。**设置匹配域名 / 添加当前域名 / 重置默认域名** 继续保留。

后续仅更换域名时，在该菜单保存新域名并刷新页面即可，无需重新导入历史。脚本会保留历次配置过的论坛域名，连续更换或重置域名后，旧域名的资源/进度链接仍可转换到当前域名。资源 ID、标题/番号索引和版块进度使用与域名无关的存储键；旧版本没有域名别名设置时，首次修改会自动保留原域名。开启“保存批量打开记录”后，动态加载完成的帖子标题也会补存，用于资源 ID 改变时按番号/标题继续识别；若站点同时更换 ID 和标题且没有对应关系，仍不能保证匹配。关闭保存记录后不写入这些记录。

**历史记录兼容**：旧版 Discuz 的 `tid:<数字>` 继续保存在 `x1080x-ex:agaghhh-batch-open-history`，不会被新版记录覆盖或截断；新版 `resource:<ID>` 单独保存。新版标记、跳过已浏览和定位进度共用标题/番号别名及已缓存的 TID 迁移结果，迁移中断后也能继续使用已匹配部分。也可读取序列化 JSON、数字 TID，以及含 `tid` / `url` / `title` / `resource_id` 的记录对象；有标题或新版 ID 的记录可直接参与匹配。新版列表自动尝试最近 100 条旧 TID，优先请求当前域名的旧帖地址，再尝试旧域名；每批匹配立即保存，并刷新按钮数量。需要完整检查时，在 Tampermonkey 菜单执行「迁移旧版 x1080x 浏览记录到新版」。

「检查旧版浏览记录」菜单只读显示当前这份脚本中的旧 TID 数、已取得对应信息数、待匹配数和新版记录数，用于区分数据没找到和数据已读到但缺少映射；不会读取浏览器原生历史，也不会删除或重写旧存储。

只有旧 TID、没有标题或新旧 ID 对应关系时，必须依赖站点仍提供旧帖/跳转，才能恢复对应记录。欢迎页、会员页不会被误判为迁移成功；无法解析的旧数据保留，不能保证全量恢复。Chrome 自身的 `:visited` 数据无法由脚本读取。

### 从本机 Chrome 访问历史恢复旧 TID

旧站已经不提供帖子时，可以用旧帖访问时留下的网址和标题补回对应信息。这属于现有浏览记录功能的手动修复流程，不会自动扫描浏览器数据。

1. 将旧 TID 数组保存为 `.local-history-recovery/old-history.json`。该目录已加入 Git 忽略规则，用于本机数据，不随代码提交。
2. 使用 Node.js 22.13+，双击 `scripts/export-legacy-history.cmd`，选择当时 Chrome 配置目录中的 `History` 文件。可在 Chrome 的 `chrome://version` 页面查看「个人资料路径」，便携版或多个配置也按此路径确定。工具以只读方式查询旧论坛网址和标题，只输出命中旧 TID 的记录。数据库若提示被占用，退出 Chrome 后重试。
3. 在油猴菜单选择「导入旧论坛历史恢复文件」，先打开页面内的导入弹窗，再点击文件控件选择生成的 `recovery-日期时间.json`，最后点击「导入」。选择文件本身不写入数据；处理结果和错误会在弹窗中显示。脚本将补充映射并刷新当前页的已浏览标记、未浏览数量及进度记录。

导入仅合并当前已有旧 TID 的映射；不会改写原始 TID 数组，并另存导入前的迁移缓存和索引。恢复标题保存在独立键中，旧版本标签页写回迁移缓存时也不会覆盖它。缺失标题、安全验证页标题、冲突番号和其他网站记录均跳过，最终以导入弹窗的实际匹配数为准，不能保证恢复浏览器已经删除的记录。

启动工具会先检查 Node.js、工具文件和旧记录清单；错误保留在窗口中，并尽可能保存到 `.local-history-recovery/export-error.log`。请保留完整项目和本地数据目录，不要单独移动 CMD 文件。命令行执行 `scripts/export-legacy-history.cmd --check` 可只检查启动条件，不打开文件窗口、不读取浏览器历史。

命令行等效用法：

```powershell
node scripts/recover-legacy-history.mjs --history "C:\path\to\Chrome\Profile\History" --legacy ".local-history-recovery/old-history.json" --output ".local-history-recovery/recovery.json"
```
